## SERIAL REFERENCE — commands use `=`, NOT a space
`:ledtest=<n>` arms a pattern — **0** off · **1** white (DOA/power) · **2** grad-grey · **3** grad-blue · **4** grad-red · **5** grad-amber · **6** grad-blend (teal↔magenta) · **7** grad-perc-blue (f²·², dark-detail) · **8** grad-mid (mid-tone) · **9** grad-warm · **10** grad-full (full-range CONTROL, does NOT band) · **11** walk (seam px79/80) · **12** checker. ## FLASH + READBACK PROTOCOL (hardware discipline — non-negotiable)
1. Identity by chip, NOT port (ports drift). Bench = **B489A500** = USB serial `B4:3A:45:A5:89:B4`. Main K1 = `F887A500` — **never touch**. Enumerate: `python3 -c "import serial.tools.list_ports as lp;[print(p.device,p.serial_number) for p in lp.comports() if 'usbmodem' in p.device]"`.
2. Pin: `python3 scripts/platformio/k1_session_target.py pin --chip-id B489A500 --upload-port <port> --capture-port <port> --env k1_bench_ws2816_1313_16bit --purpose "..." --ttl-seconds 3600`.
3. Verify: `python3 scripts/platformio/k1_upload_guard.py --env k1_bench_ws2816_1313_16bit --upload-port <port> --require-session-pin`.
4. Flash (esptool needs a pty; console truncates — trust runtime readback): `script -q <log> pio run -e k1_bench_ws2816_1313_16bit -t upload --upload-port <port>`.
5. Readback = the proof. Serial **no-DTR open** (DTR-toggle re-enumerates the native USB-JTAG → benign `rst:0x15`, looks like a crash but isn't). ## KEY FACTS / TRAPS
- All WS2816 work is bench-only; WS2816 is NOT a ratified production part. `k1_hardware`/`k1_prod_im73d` stay byte-identical.
- Never run two `pio run` concurrently (SCons `.sconsign` race → spurious `.d`-file failures). pytest (host g++) does NOT race with one pio build.
- The research crux (verified): WS2816's 16-bit depth is **unrealised in the stock FastLED path**; its real wins are low-light banding + 10 kHz PWM camera-flicker, NOT brightness/gamut.
- LED_FPS ~200 on the split (2× the 100 FPS target); the wire is 48 bits/pixel whether packed 8- or 16-bit, so depth is "free at the wire."
