## Evidence: Point-by-Point Attack

### 1. Ring linearisation order (oldest → newest)

**Claim to attack:** `sb_spectral_index` is advanced *after* the write, so it points to the next-write slot = the *oldest* sample; k=0 in the linearisation loop therefore reads the oldest sample, and k=511 reads the newest.

**Verification:**
- Emit path (lines 542–544): `decay-all → write[sb_spectral_index] = sample → sb_spectral_index++`. After advance, `sb_spectral_index` is the *next* slot to be written, i.e., the slot that was *last* written one full rotation ago — the oldest.
- Linearisation (line 234): `(sb_spectral_index + k) % 512`. At k=0 this reads `sb_spectral_index` = oldest. At k=511 this reads `sb_spectral_index - 1` = newest.
- Confirmed with unit test B5: after emitting (0.0, 1.0), `work[0]` = 0.0 (oldest), `work[511]` = 1.0 (newest). **PASS.**
- **Order is correct for ACF.** ACF at lag τ computes `Σ w[t]·w[t-τ]` which needs the sequence to be time-ordered oldest-to-newest. It is.

### 2. Decay direction vs ACF

**Claim to attack:** the per-emit `SB_NOVELTY_DECAY = 0.999` multiplied over all samples before each write creates a non-uniform exponential window, potentially invalidating the ACF.

**Finding:** the taper is intentional and gentle. The oldest sample (511 emits ago) is weighted at `0.999^511 ≈ 0.60`. This acts as a soft exponential window on the ACF — it down-weights stale beats, which is the stated design goal. Mean-subtraction still operates on the tapered sequence, which is correct (zero-mean requirement for ACF is satisfied on the windowed signal). **Not a bug.**

### 3. Biased ACF loop bounds

**Claim to attack:** the inner loop `for t = lag .. SB_HISTORY_LENGTH-1` might have an off-by-one or fail to cover enough lags.

**Verification:** standard biased ACF definition is `R[τ] = (1/N) Σ_{t=τ}^{N-1} x[t]·x[t-τ]`. The firmware omits the 1/N normalisation (which cancels in the max-normalisation step). The loop runs `t = (uint16_t)lag .. 511`, giving `512 - lag` terms — the full valid overlap. No off-by-one. **PASS.**

Manual check: for a known 8-sample signal, lag=2 ACF matched expected value −3.0 exactly.

### 4. Lag band [lag_min, lag_max] coverage of 60–155 BPM

**Numerical values at SB_NOVELTY_RATE_HZ = 44.444 Hz:**

| | Value |
|--|--|
| `lag_min` | `floor(44.444×60/160) − 1 = 16 − 1 = 15` |
| `lag_max` | `ceil(44.444×60/55) + 1 = 49 + 1 = 50` |
| `nlag` | `50 − 15 + 1 = 36` (well below the 64 cap) |

**Extreme bin coverage:**
- 60 BPM: `lag_real = 44.444×60/60 = 44.44`, `L0 = 44`, `c = 44−15 = 29`. Parabolic branch: `c≥1 && c<35` → YES.
- 156 BPM (note: actual max bin is 155 BPM; see §7): `lag_real = 44.444×60/156 = 17.09`, `L0 = 17`, `c = 17−15 = 2`. Parabolic branch: `c≥1 && c<35` → YES.

**All 96 bins fall inside the parabolic branch.** The fallback `else if (c >= 0 && c < nlag)` is never reached for the actual BPM range. **PASS.**

### 5. Parabolic interpolation formula correctness

**Formula (line 266):**
```
val = y0 + 0.5*frac*(yp - ym) + 0.5*frac*frac*(yp - 2*y0 + ym)
```
where `frac = lag_real - floor(lag_real)` ∈ [0, 1).

**Algebraic verification (Newton/Lagrange quadratic through (−1,ym), (0,y0), (1,yp)):**
- frac=0 → `y0`. Correct.
- frac=1 → `y0 + 0.5(yp−ym) + 0.5(yp−2y0+ym) = yp`. Correct.
- frac=−1 → `y0 − 0.5(yp−ym) + 0.5(yp−2y0+ym) = ym`. Correct.

The formula is the standard second-order Lagrange interpolant evaluated at `frac` relative to `y0`. It is used to *interpolate* the ACF at the real (non-integer) lag, not to *find* the parabolic peak — which is the correct use here. **PASS.**

### 6. `lag_real` units

**Formula (line 259):** `lag_real = SB_NOVELTY_RATE_HZ × 60 / bpm`.

Units: `(samples/sec) × (sec/beat) = samples/beat`. For 120 BPM: `44.444 × 60 / 120 = 22.22 samples`. The ACF array is indexed in samples at the novelty rate. Lag in samples at 44.444 Hz corresponds to the inter-beat period at the target BPM. **Units correct.**

### 7. Normalisation, `sb_acf_valid` gate, warm-up

- `smax` is initialised to `1e-12f` (guard against zero). All saliences are divided by `smax`. `sb_acf_valid` is set true only when `smax > 1e-6f` (i.e., the ring has meaningful energy). Until then `sb_sel_score()` falls back to the de-quartic Goertzel score. **Correct guard.**
- No warm-up counter is needed: the ring fills to full 512 samples before ACF is useful; the `smax` gate naturally rejects the cold-start phase.

### 8. Minor cosmetic comment inaccuracy (not a bug)

`SB_NUM_TEMPI = 96`, `SB_TEMPO_LOW = 60.0`. Bin `i` maps to BPM `60 + i`, so i=95 → 155 BPM. The comment at line 10 states "60..156 BPM" but the actual range is **60..155 BPM**. The `lag_min/lag_max` margin (55..160 BPM) correctly over-covers this range. No accuracy impact. The unit test's `[156BPM]` case tests a value outside the bin array; peak correctly lands at 155 BPM (nearest bin, within tolerance).

## Why the 40.6% Acc2 gap is NOT explained by a code bug

The ACF implementation is mathematically correct. The gap between firmware 40.6% Acc2 and the 53% host ceiling must be attributed to:

1. **Real-time resource constraints** — `sb_compute_acf_salience()` is called every emit (44.44 Hz). The host can afford full-length ACF with windowing; firmware uses biased ACF over a 36-lag band only.
2. **Exponential window asymmetry** — the SB_NOVELTY_DECAY taper is not a standard analysis window; its effect on the ACF peak shape differs from a rectangular or Hann window.
3. **Goertzel–ACF coupling** — `sb_sel_score()` multiplies `sb_acf_salience[i]` by `sb_tempo_prior[i]` (log-Gaussian tactus prior). If the prior's centre or width is mismatched to the test corpus, it will suppress true-BPM bins.
4. **Novelty signal quality** — the ACF operates on novelty, which on real music is noisier than a synthetic metronome; the host ceiling of 53% is measured on the same novelty, so this is a shared limit.
5. **Octave ambiguity** — the ACF has no explicit octave-defence mechanism (unlike the host pipeline). Sub-harmonic peaks at half-BPM are strong in the ACF and may win selection.

These are tuning and architecture gaps, not implementation errors.
