## 2. Scorer audit — key lines quoted

**`tempo_accuracy.py`** (lines ~30–35, ~162–175):
```python
TOL    = 0.04                              # ±4% relative — MIREX-style
OCTAVES = [1.0 / 3.0, 0.5, 1.0, 2.0, 3.0] # five relations inc. x1/3, x3
BPM_LO, BPM_HI = 60.0, 155.0              # in-range gate

def octave_eval(det, gt):
    acc1 = abs(det - gt) / gt <= TOL
    errs = [(abs(det - k * gt) / (k * gt), k) for k in OCTAVES]
    best_err, best_k = min(errs)
    return bool(acc1), bool(best_err <= TOL), best_k, best_err
```

**`acf_ceiling_sweep.py`** (REUSE CONTRACT preamble, lines 20–30):
```
Scoring: tempo_accuracy.octave_eval (Acc1 exact, Acc2 octave-tolerant) + TOL +
OCTAVES + BPM_LO/BPM_HI in-range gate.
```
The sweep imports `octave_eval`, `TOL`, and `OCTAVES` directly from `tempo_accuracy`.
Byte-identical confirmed.

**`acf_gap_ablation.py`** (line 53, line 297):
```python
import tempo_accuracy as ta
a1, a2, _, _ = ta.octave_eval(det, g["bpm"])
```
Also byte-identical confirmed.

**`ac_ceiling_bpm()` in `tempo_accuracy.py` (lines ~162–176) — oracle:**
```python
def ac_ceiling_bpm(nov, lo_bpm=55.0, hi_bpm=210.0):
    x = nov - nov.mean()
    ac = np.correlate(x, x, "full")[len(x) - 1:]
    if ac.size: ac[0] = 0.0
    fps = nfw.SAMPLE_RATE / nfw.HOP
    lo = max(1, int(round(fps * 60.0 / hi_bpm)))
    hi = int(round(fps * 60.0 / lo_bpm))
    lag = lo + int(np.argmax(ac[lo:hi]))
    return 60.0 * fps / lag
```
This is a **single whole-clip `np.correlate`** (full mode) — non-causal, offline,
global argmax. It sees the entire track in one shot. This is fundamentally different
from the firmware's causal frame-by-frame winner-selection loop.

## 4. Verdicts per claim

### C1 — Firmware Acc1 28.1% / Acc2 40.6% / octave-err 12.5%; baseline 25.0/28.1/3.1
**CONFIRMED.**
The per-track CSV cross-check reproduces 28.1% / 40.6% in-range exactly with the wide set,
and identical 28.1% / 40.6% with the MIREX-standard set — zero inflation on this corpus.
The octave-error rate (Acc2 − Acc1 in-range) = 40.6% − 28.1% = **12.5%** ✓.
The "baseline" figures (25.0% / 28.1%) are the all-track / in-range Acc1 respectively ✓.
One caveat: the "baseline" label has been applied to different things across reports —
`tempo_accuracy.py` docstring describes the current run as the _committed_ firmware,
not a pre-ACF step. There is no separate pre-ACF re-run in this back-test; 25.0/28.1
are the all/in-range Acc1 for the same firmware run. Treat "baseline = 25.0/28.1" as
the all-track / in-range Acc1 split, not a pre-ACF predecessor run.

### V-SCALE-A — Byte-identical scoring across all three scorers
**CONFIRMED.**
`acf_ceiling_sweep` and `acf_gap_ablation` both import `octave_eval`, `TOL`, `OCTAVES`,
`BPM_LO`, `BPM_HI` directly from `tempo_accuracy`. No local re-definition. Identical by
import, not by coincidence.

### V-SCALE-B — Acc2 forgiveness set {1/3, 1/2, 1, 2, 3} wider than MIREX {1/2, 1, 2}
**CONFIRMED — but inflation is zero on this corpus.**
The set is structurally wider (adds x1/3, x3). However, on 36 HarmonixSet tracks, no
track lands in Acc2 exclusively via x1/3 or x3. The de-inflated MIREX score is
numerically identical. The inflation risk is real for other corpora (especially tracks
at 180+ BPM where x1/3 ≈ 60 BPM is reachable), but does not affect these numbers.

### V-SCALE-C — 53% is a non-causal whole-clip oracle vs the causal firmware 40.6%
**CONFIRMED.**
`ac_ceiling_bpm` uses `np.correlate(..., "full")` on the entire clip's novelty vector
in a single offline pass — whole-clip, non-causal. The firmware's `sb_tempo` processes
frames sequentially through a 512-sample decayed ring, winner-hysteresis, and a
log-Gaussian tactus prior. The scoring _function_ is shared; the _detector_ being
scored is architecturally different. The 53% figure is an upper bound, not a peer score.

## 5. Sanity vs literature

Acc2 (MIREX {1/2,1,2}) ±4% of **36–40%** for a flux-novelty ACF-based tracker on
HarmonixSet is **plausible and slightly below mid-range** for this class of algorithm.
Published state-of-the-art (Böck et al. 2015 DBN, Percival & Walters 2014) reaches
70–84% Acc2 on Ballroom/HarmonixSet. A pure-flux Goertzel/ACF system without beat
tracking is expected in the 40–60% region; 40.6% at the low end is consistent with
the dominant failure mode being low-bin pinning (18/36 "off"), not octave confusion —
which is also consistent with `x1:13, x2:5, off:18` from the histogram. The numbers
are not suspiciously inflated; if anything they reflect a real winner-selection weakness.
