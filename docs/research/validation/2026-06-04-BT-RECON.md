## Claim #2 — ACF Ceiling

### Sweep results (re-run, 36 tracks, in-range 60–155 BPM = 32 tracks)

| config (rate / interp / conditioning) | Acc2 (in-rng) | Acc1 (in-rng) |
|---|---|---|
| 133.33 Hz / int / raw | 53.1% | 21.9% |
| 133.33 Hz / int / log1p | **56.2%** | 25.0% |
| 133.33 Hz / parab / raw | 56.2% | 21.9% |
| 133.33 Hz / parab / log1p | **56.2%** | 25.0% |
| 44.44 Hz / int / raw | 46.9% | 12.5% |
| 44.44 Hz / int / log1p | 43.8% | 15.6% |
| 44.44 Hz / parab / raw | 53.1% | 12.5% |
| 44.44 Hz / parab / log1p | 50.0% | 15.6% |

**TRUE ceiling: 56.2% at 133.33 Hz / log1p (or 133.33 Hz / parab / raw — same score).**
Best single combination for Acc1+Acc2: `133.33 Hz / int / log1p` (56.2% Acc2, 25.0% Acc1).

**44.44 Hz / int / raw sub-ceiling: 46.9%, NOT 53.1%.**
53.1% at 44 Hz requires parabolic interpolation (`44.44 Hz / parab / raw`).
Without parabolic interp, firmware-rate integer-argmax tops at 46.9%.

### Verdict

- **SSA T4 was wrong on two counts:** (a) it called 53% the ceiling — the true ceiling
  is 56.2%; (b) it attributed 53% to `44Hz/parab/raw` as the firmware sub-ceiling, but
  `44Hz/int/raw` (the actual firmware condition — no parabolic interp is currently
  implemented in `sb_tempo`) scores only 46.9%.
- **SSA V-RECON was correct** that 56.2% is the true ceiling and that it belongs to the
  133 Hz / log1p configuration. It was also correct that 53% is only a sub-ceiling. It
  did not explicitly separate the `int` vs `parab` split at 44 Hz, which is a secondary
  gap but not a material error.
- **The firmware-rate (44.44 Hz) integer-argmax Acc2 = 46.9%, stable on re-run.**
  The 53.1% figure for 44 Hz only holds with parabolic sub-lag interpolation.

## Claim #7 — v3 Octave Arbiter

### Does `esv11_pick_top_tempo_bin_octave_aware()` exist in v3?

**YES.** Defined at
`firmware-v3/src/audio/backends/esv11/vendor/tempo.h:372` (inline function).
Called at `EsV11Backend.cpp:182` (production path, inside `refreshOutputs()`) and
again at `EsV11Backend.cpp:381` (diagnostics path).

### Exact form (load-bearing edges)

```cpp
// vendor/tempo.h:372-420 (verbatim)
inline uint16_t esv11_pick_top_tempo_bin_octave_aware() {
    const uint16_t raw_bin = esv11_pick_top_tempo_bin_raw();
    const float raw_mag   = fmaxf(tempi_smooth[raw_bin], 1e-6f);
    const float raw_bpm   = static_cast<float>(TEMPO_LOW + raw_bin);

    uint16_t selected_bin   = raw_bin;
    float    selected_score = raw_mag;

    const int16_t double_bin = esv11_bpm_to_bin(raw_bpm * 2.0f);
    if (double_bin >= 0) {
        // --- persistence gate ---
        static uint8_t octave_double_persist = 0;
        const bool want_double = (raw_bpm < 80.0f && tempo_confidence > 0.06f);
        if (want_double) { if (octave_double_persist < 255u) ++octave_double_persist; }
        else             { octave_double_persist = 0u; }
        if (octave_double_persist >= 50u) {               // <-- gate: 50 consecutive calls
            selected_bin   = static_cast<uint16_t>(double_bin);
            selected_score = esv11_pick_local_bin_magnitude(double_bin, 1);
        }

        // --- magnitude-ratio test ---
        const float double_mag       = esv11_pick_local_bin_magnitude(double_bin, 1);
        const float ratio            = double_mag / raw_mag;
        const float ratio_threshold  = (raw_bpm <= 72.0f) ? 0.56f : 0.72f;  // <-- thresholds
        if (ratio >= ratio_threshold && double_mag > selected_score) {
            selected_bin   = static_cast<uint16_t>(double_bin);
            selected_score = double_mag;
        }
    }
    // ... edge-rebound and half-time recovery follow
}
```

**Key constants (extracted verbatim):**

| Parameter | Value | Location |
|---|---|---|
| Persistence gate count | **50 consecutive calls** (~200 ms @ 250 Hz) | `tempo.h:395` |
| Ratio threshold (raw_bpm ≤ 72 BPM) | **0.56** (double_mag / raw_mag) | `tempo.h:403` |
| Ratio threshold (raw_bpm > 72 BPM) | **0.72** (double_mag / raw_mag) | `tempo.h:403` |
| Confidence floor for enter | **0.06** (tempo_confidence) | `tempo.h:389` |
| Magnitude domain | **tempi_smooth[]** (Goertzel smoothed bank) | `tempo.h:374,400` |

The arbiter also has a secondary `EsV11Backend`-layer (in `refreshOutputs`) that adds
BPM-ratio hysteresis using `TempoParams` (`octRatioLo=1.9`, `octRatioHi=2.1`,
`octaveRuns=4` consecutive `refreshOutputs` calls, `holdUs=200000 µs`). These are the
*bin-switch stability* layer on top of the picker; the magnitude-ratio test above lives
entirely inside `esv11_pick_top_tempo_bin_octave_aware()` in `vendor/tempo.h`.

### Verdict

- **SSA T2 was wrong.** v3 is not "Goertzel-only, no ACF/prior/arbiter". It has a
  production octave arbiter (`esv11_pick_top_tempo_bin_octave_aware`) that is called in
  the main DSP path (`EsV11Backend.cpp:182`) on every chunk.
- **SSA V-RECON was correct** that the function exists, is called at `EsV11Backend.cpp:231`
  (confirmed; also called at :182 and :381), and is used in production.
- **Portability as a donor:** YES, with one qualification. The magnitude-ratio test and
  persistence gate are self-contained against `tempi_smooth[]` (Goertzel smoothed bank)
  and `tempo_confidence` — both are pure Goertzel-domain scalars. The ratio thresholds
  (0.56 / 0.72) and gate count (50) are numeric constants with no ACF dependency. The
  function is a clean donor for the K1 fork's octave-correction layer, provided the
  receiving code has access to a comparable smoothed Goertzel magnitude bank.
