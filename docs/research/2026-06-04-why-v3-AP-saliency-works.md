# Why v3 AP saliency works: fork failure source and concrete fix

- **ONE AP property that fixes precision/recall in v3:** v3’s AP conditioner does **log-domain, hop-aligned, gate-gated flux/rms conditioning before saliency**, not just the v3 formula. `PipelineCore::computeLogFlux()` uses `log1p`-domain bin flux + derivative gating, `PipelineAdapter` applies `scaledFlux = flux * fluxScale` then `scaledFlux/(1+scaledFlux)` (bounded compression), and `ControlBus::UpdateFromHop`/`applyDerivedFeatures` clamp+smooth all derived values before `computeSaliency`; this is absent in fork (`sb_audio_snapshot` passes raw `novelty_curve` and raw spectral sums directly into saliency). See: `Lightwave-Ledstrip/firmware-v3/src/audio/pipeline/PipelineCore.cpp`, `Lightwave-Ledstrip/firmware-v3/src/audio/pipeline/PipelineAdapter.cpp`, `Lightwave-Ledstrip/firmware-v3/src/audio/contracts/ControlBus.cpp`, `SPECTRASYNQ_K1_FIRMWARE/audio/sb_audio_snapshot.cpp`, `SPECTRASYNQ_K1_FIRMWARE/audio/sb_musical_saliency.cpp`.

- **Why fork gives precision 0.21 / recall 0.003 / more silence hits:** in fork, the AP feature rate is still decimated (`samples_per_chunk=96`, 12800Hz) and novelty remains effectively unnormalised/raw (`sb_audio_snapshot` sets `novelty = clamp_nonnegative(novelty_curve[idx])`, no log scaling or gate suppression), while v3 conditions features at a coherent 125Hz hop path (`32kHz/512 FFT` context) with Schmitt RMS silence gating (`open=0.02/close=0.005`) and frame-state hold. This mismatch makes weak noise pass as salient timbral change in silent music-like conditions, causing very high false positives in silence and very low true positives on music (hence low recall).

- **Concrete fork fix (minimum viable):** 1) port v3 AP conditioner into snapshot production: compute log-domain band/flux deltas, clamp and compress (`f/(1+f)`), and reuse AGC-normalised scaling before writing `SBAudioSnapshot` fields; 2) apply same silence gate and hold semantics as v3 (open 0.02 / close 0.005 with counters) so derived features are zeroed/held when gated; 3) align AP hop timing to v3 AP cadence (32k pipeline/512 window expectation) before feeding `sb_musical_saliency_update`, while keeping saliency thresholds and `dt`-style asymmetry from `sb_musical_saliency` untouched. This is a feature-conditioning repair, not a formula rewrite.
