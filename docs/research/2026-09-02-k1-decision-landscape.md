## Ruling order — why this sequence and not another

1. **D4 hardware fork** and **D6 sequencing** together: if K1-DM-040 (silicon) goes first, the board identity must be frozen now; if K1-DM-020 (DSP parity) goes first, D4 can wait but D1 cannot.
2. **D1 sample rate** before any parity port. It is the one ruling that invalidates goldens; everything downstream (24 kHz hi-hat band, A-weighting, FFT-flux novelty) depends on it.
3. **D2 schema transport** before Tab5 P4 tier-2 work. It is a two-way door technically (SysEx and GATT can coexist) but a one-way door for the deck's information architecture.
4. **D3 calibration mechanism** as an analysis lane in parallel; it touches the SSL defect that is still open on the bench.
5. **D5 product scope** last — each item is independent and none blocks a firmware lane.

## Steel-man, red team, map–territory (kept short)

- *Steel-man:* "Finish the S3 product first; the DualMCU is a distraction." Closed 27 Aug (Q0-A) on the compute-wall premise (~22 µs headroom, 30/16 000 frames already over budget before the int64 promotion). It reopens only if a fresh measurement on current silicon disproves that premise — which nobody has taken since the promotion landed.

The 24 Aug audit already caught green gates decoupled from working firmware once. The harness restructure is the only structural difference; if it slips, the analogy completes.
