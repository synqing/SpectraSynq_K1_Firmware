The short answer

A LUT is a function RGB → RGB. If that function lives in RAM or flash as a table, Core 1 can point at a different table on the next frame. That is a runtime look switch. No rebuild. No reflash.

What you have tonight is the opposite: K1_WS2816_DEGAMMA_V1 is an #ifdef. Off means the function is not in the binary. On means one curve, always, every pixel, both DINs. That is a build look, not a library.

Palettes are already a library. :palette_index=29 picks which colours the show is painted with. A look library would sit after that painting, and decide how those codes hit the WS2816 silicon. Same song, different print.

The four words, unpacked

1. Per-channel

Three 1D tables: one each for R, G, B. Same shape? That is tonight’s degamma — a print curve, not a gel. Different shapes? Now you can warm or cool the plate, kill a green spike, or hold blue in the darks.

Memory: 256 × 3 × 2 bytes = 1.5 KB. Switch: swap three pointers.

2. 3D

A cube of RGB nodes. Input colour indexes a cell; the output is interpolated from the eight corners. The look can depend on the mix: saturate only the reds, rotate only the cyans, leave neutrals alone.

That is why film scanners and cameras ship .cube files. A 1D LUT is a tone curve. A 3D LUT is a grade.

3. Authored

Someone decided the numbers. Not pow(v, 1/2.2) generated at compile. A colourist, or you, or a measured chart of this exact LGP + WS2816C batch.

Authored looks live as data: arrays in flash, later a file. Generated looks are formulae wearing a LUT costume. Tonight’s table is generated. A library wants authored slots plus one generated identity.

4. Flag-off identity

When the feature is compiled out, or slot 0 is selected, the function is return rgb. No table walk. No “almost identity” lerp error. The plate matches last night’s Lever-2 ship.

This is the same law as ENABLE_OUTPUT_GAMMA 0 and as :palette_hd=off. Off is a first-class look named Identity, not the absence of care.

Can it switch at runtime? Yes — here is the shape

Core 1 already owns the show. A look is just another buffer that stage reads. The safe switch is a pointer swap at the start of a frame, never mid-pixel.

Slot 0 is law

look_apply(rgb, 0) == rgb

Compile the identity as a function, not a table of 0,1,2,… so there is no lerp dust. Slots 1…N are tables in flash. :look=0 is last night. :look=1 can be tonight’s degamma if you still want it as a print, not as destiny.

Where the bytes live

Phase A — compiled slots. Four looks in PROGMEM. Serial :look= picks one. No upload path. No LittleFS. This is the whole first ship.

Phase B — load. Tab5 or USB writes a slot into PSRAM or LittleFS. Checksum, version, LED-count-agnostic (it is a colour map, not a pixel map). Still applied on Core 1 only.

Why this is not a palette

A palette answers “which yellow.” A look answers “what does that yellow become on this silicon, in this room.” You can keep palette 29 and flip looks. You can keep Identity and flip palettes. Mixing them into one blob is how you lose revert.

What it costs on this chip

ESP32-S3: 512 KB SRAM, 8 MB PSRAM, 16 MB flash. Visual canvas 160 LEDs × two DINs. Target ~100–135 FPS. Numbers below are exact for packed RGB u16.

Proposal — a look library, not another #ifdef

Not built. Not on silicon. One stage, four compiled slots, serial switch, Identity as slot 0. Degamma becomes slot 1 so you can A/B it against the bench without a flash.

SlotNameMachineWhy it exists

1Degamma 2.2shared 1DTonight’s curve, now optional
2Tungsten trimper-channel 1DProve WB is a look, not a myth

Command shape, matching the palette habit: :look=0 persist in NVS. Tab5 later gets a wheel. No look upload in phase A — authored slot 3 stays identity until a chart exists. Do not invent a film grade in firmware.

The August 18 S9 audit already said the “8-bit path has gamma, Lever-2 does not” premise is false. A library does not re-litigate that. It gives you a print selector so a curve is a choice, not a religion.
