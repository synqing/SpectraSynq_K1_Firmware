## Refuted / not in this defect class
- `K1_MIC_IM69D_INPUT_GAIN` (constants.h:108, 4.0f) and `K1_MIC_IM73D_INPUT_GAIN` (constants.h:86, 16.0f) — these ARE the IM69D-specific re-derivation (Phase 0 gain retune, 1ae9d4a, 2026-08-05); correctly scoped, not stale.
- `K1_MIC_IM69D_RAW_I16_NEAR_RAIL` / `K1_MIC_IM73D_RAW_I16_NEAR_RAIL` (both 30000) — each independently defined inside its own mic `#ifdef` block; not a shared-fallthrough case, and both comments state "measurement-purity surface" (int16 rail proximity), not a tuned noise-floor value. Same numeric value on both mics is plausible (int16 range is mic-independent) — not flagged as stale by inference alone.
- `SILENCE_ENTER_SSL_FRAC` / `SILENCE_EXIT_SSL_FRAC` (globals.h:692-693, 0.35f/0.55f) — comment explicitly labels these "DEGRADED-MODE first-guesses... tunable at runtime," not a hardware-characterised value scoped to one mic. Different failure class (acknowledged-provisional, not silently-stale).
- `calibration/noise_cal.h` — contains no hardcoded RMS/gain constants; calibration is dynamic (percentile-learned), so no stale-constant risk in this file itself (it consumes the constants.h values above).

## Pattern found (matches orchestrator's template exactly)
Three constants share the identical defect shape as `K1_SILENCE_RMS_ENTER/EXIT`:
`NOISE_CAL_SSL_TRUSTED_P90_MAX_RAW`, `NOISE_CAL_SSL_MAX_VALID_RAW`, `WAVEFORM_REACTIVE_RAW_MARGIN`.
All three have a **mic-specific override that exists ONLY under `#ifdef K1_MIC_IM73D_PDM_V1`**, with
**no corresponding `#ifdef K1_MIC_IM69D_PDM_V1` override** — so an IM69D build silently falls through
to either the IM73D value (wrong mic) or, for the two SSL constants, all the way to the base
SPH0645-domain value (wrong mic, wrong generation). This is a structural gap (missing #ifdef branch),
not just a stale comment — grep for `K1_MIC_IM73D_PDM_V1` vs `K1_MIC_IM69D_PDM_V1` block coverage in
constants.h is the reproducible signature.
