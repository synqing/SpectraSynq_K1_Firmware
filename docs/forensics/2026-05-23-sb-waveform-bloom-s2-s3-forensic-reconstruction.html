Executive Reconstruction

Short version: the Bloom and Waveform visual fixes are present in current source, but their fine-grained repair history predates the local git commit stack and must be reconstructed from memory/session records plus current source proof. The S2-S3 work evolved into a K1 hardware bring-up profile using firmware-v3 GPIOs, with compile/upload evidence recorded, followed by uncommitted hardening for absent Rotate8, USB serial strategy, LEDC guard failures, and K1 hardware compile flags.

Bloom

The key transport-history bug was fixed: Bloom now snapshots leds_prev_buffer immediately after centre insert and before display-only edge fade and mirror. This prevents faded/mirrored display output from recursively poisoning the transport history.

Palette

The palette white/grey crush path was removed from palette-owned branches. Palette colour is now sampled once through palette_chroma_colour(); palette branches no longer raw-add twelve ColorFromPalette() RGB samples into current_sum_color.

Modes 7/8

The broken-right-side mirror behaviour was fixed by making mirrored WAVEFORM-FAST and WAVEFORM render an upper-half authoritative trace and mirror from there. Non-mirrored mode preserves the old full-strip oscilloscope trace.

Hybrid

WAVEFORM-HYBRID remains a separate centre-origin outward-trail mode using waveform_shift_outward() and optional waveform_history. The visual probe now seeds waveform_history deterministically when present.

K1 hardware

The migration moved from generic S3 compile prep to an explicit K1 hardware profile: LED GPIO 6/7, I2S 13/11/14, I2C 17/18, physical controls disabled, with compile/upload evidence recorded against ESP32-S3 MAC b4:3a:45:a5:87:f8.

Not Proven

The latest dirty K1 hardware hardening has compile/upload history nearby, but current runtime proof remains incomplete: no confirmed serial smoke after the latest LEDC guard patch, unresolved PSRAM ID error, no I2S/LED/timing proof for the latest binary.

Stratum A - Waveform Dies After Noise Calibration

This was the earliest waveform failure lane. It is not the same as the palette/mirror bugs, but it matters because several later repairs happened on top of a source base already shaped by that investigation.

Question Finding Evidence

Stratum B - Bloom Transport History Corruption

The specific Bloom bug was that the mode inserted centre colour, applied edge fade, mirrored, and only then copied the frame into leds_prev_buffer. That meant display-only attenuation became recursive transport history. The result was Bloom dying before it reached the edges.

Current source proof:
SPECTRASYNQ_K1_FIRMWARE/lightshow_modes.h:944-951
  leds_16[center_idx1] = final_insert_color;
  leds_16[center_idx2] = final_insert_color;

  // Snapshot transport history before display-only edge fade and mirror.
  memcpy(leds_prev_buffer, leds_16, sizeof(CRGB16) * NATIVE_RESOLUTION);

SPECTRASYNQ_K1_FIRMWARE/lightshow_modes.h:955-974
  uint16_t fade_width = NATIVE_RESOLUTION / 4;
  ...
  mirror_image_downwards(leds_16);

This proves the required ordering: transport history is captured before the display fade and mirror.

Stratum C - Palette White/Grey Crush

The palette bug was that palette mode sampled multiple note anchors and accumulated RGB values, which compresses gradients toward grey/white and loses palette structure. The correction was to compute palette position separately from brightness and sample the palette once.

Current source proof:

Important nuance: memory observation #54002 specified a simple weighted index using sum(raw_bin * c/12 * 255) / total_weight. Current source instead uses a circular chroma vector via cosf, sinf, and atan2f. That may be creatively better for pitch-class wraparound, but it is not the literal suggested helper implementation. The report records current truth rather than retrofitting the story.

Stratum D - WAVEFORM-FAST and WAVEFORM Broken Mirror

The broken right side came from a mismatch between a full-strip dot trace and a directional mirror helper. mirror_image_downwards() copies the second half into the first half. If the meaningful dot/state is on the wrong half, mirror can erase or ignore the intended source.

The architecture decision that survived review was narrow: do not convert modes 7/8 into WAVEFORM-HYBRID clones. Preserve OG oscilloscope identity for non-mirrored operation, but in mirrored operation make one half authoritative before mirroring.

Current source proof:

  waveform_upper_half_source_position()

SPECTRASYNQ_K1_FIRMWARE/lightshow_modes.h:1174-1184
  waveform_shift_upper_half_up()

SPECTRASYNQ_K1_FIRMWARE/lightshow_modes.h:1310-1327

SPECTRASYNQ_K1_FIRMWARE/lightshow_modes.h:1440-1453
  WAVEFORM: same mirrored branch shape.

This is not the symmetric-paired-dot version proposed during discussion. The current source uses upper-half source trace plus conditional mirror.

Contradictions and Unresolved Questions

History Compression

The most surgical Bloom/Waveform fixes are not represented as individual local git commits. They are reconstructed from memory observations and current source.

Helper Drift

The final palette_chroma_colour() implementation uses circular hue vector logic, not the originally suggested linear weighted-index formula. That may be desirable but should be treated as a real implementation difference.

Mirror Semantics

Modes 7/8 currently use upper-half source trace plus mirror when CONFIG.MIRROR_ENABLED is true. This is not the exact symmetric-paired-dot suggestion from the discussion, but it does solve the directional mirror source problem.

Bloom Mirror Toggle

Bloom still calls mirror_image_downwards(leds_16) unconditionally after fade. Whether Bloom should obey CONFIG.MIRROR_ENABLED remains a product/behaviour question.

USB Serial

K1 hardware USB strategy changed through several iterations: custom descriptors, USBCDC, hardware CDC, and USBSerial aliasing. Current source must be treated as unproven until serial smoke is captured after the latest hardening.

PSRAM

PSRAM compile flags exist and waveform_history has fallback allocation. Runtime log still included PSRAM ID read error: 0x00ffffff; that is not closed.

Performance

K1 hardware upload and compile evidence do not prove 120 FPS or a 2 ms render ceiling. Recorded perfect S2 VP render average was 1911 microseconds with max 8207 microseconds, already showing spikes.

Docs Drift

docs/s3-migration-prep.md records LoopCore=1/EventsCore=1, while current tools/compile-k1-arduino.sh uses 0/0. That must be reconciled before treating docs as current build truth.
