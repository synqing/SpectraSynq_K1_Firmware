## The slot-label contradiction this exposed

The stereo capture disagrees with the mono measurements taken earlier the same day:

| build | quiet rms | response to music |
|---|---|---|
| `hpf` (mono, **default** slot) | 80–112 | **none** |
| `hpf_slotr` (mono, `SLOT_RIGHT`) | ~7 | responds |
| stereo array 0 ("L") | **7.86** | **+19.6 dB** |
| stereo array 1 ("R") | **117.6** | **+28.4 dB** |

Two facts follow:

1. **The historical stereo array labels are inverted relative to the ESP-IDF PDM electrical
   names.**
   Mono `SLOT_RIGHT` (~7) matches stereo array 0; the mono default (80–112) matches stereo
   array 1. The active PDM header defines RIGHT as SELECT pulled up and LEFT as SELECT pulled
   down. This resembles the already documented SPH0645 naming trap but is frozen here from
   the PDM driver's own definitions, not inferred from the SPH path.
2. The earlier "no response" mono-default verdict is not evidence that IM2 is absent. The
   stereo capture proved IM2 responds. The corrected fault class is **slot semantics / source
   selection**, plus the absence of an input-integrity check.

## Slot-semantics resolution — 2026-08-15

The physical mapping is resolved without a new acoustic test. The labels are the defect:
the current source calls PCM index 0 `LEFT` and index 1 `RIGHT`, but the active ESP-IDF PDM
enumeration assigns the pulled-up microphone to `RIGHT` (`BIT(0)`) and the pulled-down
microphone to `LEFT` (`BIT(1)`).

| Layer | IM1 | IM2 | Evidence |
|---|---|---|---|
| Physical board position | silk `LEFT IM69D` | silk `RIGHT IM69D` | EDA wiring authority, line 75 |
| PCB SELECT strap | HIGH via R7 → 1.8 V | LOW via R14 → GND | EDA wiring authority, lines 90–103 |
| Infineon PDM convention | LEFT, SELECT to VDD | RIGHT, SELECT to GND | IM69D130 datasheet Figure 10 + Infineon application support |
| Active ESP-IDF PDM mask name | `I2S_PDM_SLOT_RIGHT` = `BIT(0)` = SELECT pulled up | `I2S_PDM_SLOT_LEFT` = `BIT(1)` = SELECT pulled down | active toolchain `hal/i2s_types.h`, lines 137–143 |
| Stereo PCM position | index **0** | index **1** | mono/stereo numerical cross-match below |
| Stereo quiet RMS | **7.86** | **117.60** | CRC-verified 12,800-frame capture |
| Matching mono leg | explicit `SLOT_RIGHT`, ~**7** RMS | default `SLOT_LEFT`, **80–112** RMS | same-day mono probes |
| Witnessed response in stereo | **+19.6 dB** | **+28.4 dB** | `:scap_status` |
| Independence | not duplicated; 0.32% identical samples; best offset-copy 0.34% | same paired result | 12,800-frame decoded capture |

The numerical crossover is exact in the dimension needed for ordering: mono
`SLOT_RIGHT` matches PCM index 0's floor, while mono `SLOT_LEFT` matches PCM index 1's
floor. Combined with the SELECT straps and the active driver's own enum comments, this
uniquely identifies both physical microphones.

## Cancelled procedure — not evidence for slot identity

The earlier blocking request for directed stimulus, acoustic occlusion and Primary versus
Secondary plate interpretation is withdrawn.

Both render channels consume shared processed audio, so their relative visual response
cannot identify a physical microphone. Occlusion adds uncontrolled handling noise, pressure
transients, vibration and uncertain attenuation. A directed raw-stereo crossover remains a
fallback only if the static chain is later contradicted; it is not required by current
evidence.
