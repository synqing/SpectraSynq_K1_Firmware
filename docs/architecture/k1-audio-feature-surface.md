## Conditioning summary: what is/isn’t done before feature exposure
- Spectral transport to snapshot is preconditioned by AGC, noise subtraction, low-pass, and clamping in `GDFT` before downstream feature extraction (`GDFT.h:171-179`, `182-184`, `202-279`).
- Snapshot-level feature aggregation is mostly arithmetic averaging/ratio without additional normalisation families (no explicit log compression, no bounded-ratio helper, no explicit `fluxScale`) (`sb_audio_snapshot.cpp:36-55`, `56-71`, `290-331`, `sb_clamp_nonnegative`).
- v3 saliency fields are contractually framed as bounded normalised floats (`0..1`) and use clamp points and explicit tuning thresholds/smoothing (`MusicalSaliency.h:38-40`, `ControlBus.cpp:903-905`, `910-913`, `919-931`, `936-965`).

## Top-3 conditioning gaps to v3 surface
1. K1 exposes multiple raw snapshot scalars (`spectral_energy`, per-band energies, `chroma_strength`) that are computed from AGC-conditioned spectrogram but are not expressed as v3-style bounded semantic scalar contracts (`0..1` with explicit domain policy) in this source slice.
2. K1 `novelty` remains a square-rooted positive spectral-flux aggregate; v3 timbral novelty path is thresholded/ratioed and clamp-normalised (`rms`/`flux` derivatives with `clamp01`) before smoothed state is surfaced.
3. K1 onset/bass-onset fields are declared but their conditioning path is outside the bounded read scope; v3 rhythm semantics in the cited control path include confidence+beat-tick gating and smoothing contracts.
