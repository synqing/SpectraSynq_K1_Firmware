Layout Decision

Keep the header as a separate navigation/status strip. Collapse the redundant controls into the first dashboard row below it: Primary, Secondary, and Scene become three compact touch buttons with no repeated mode, palette, brightness, colour, or speed metrics.

  • Header remains Back, K1 CONTROL, K1 AP, K1 OK, and FPS only.
  • First-row Primary and Secondary buttons are now the edge selectors.
  • First-row Scene button cycles OFF, ASSIST, L1, AUTO on each press.
  • Mode moves to the right rail as direct buttons for firmware-selectable effects only.
  • Palette remains a discrete -/+ control, but the user sees the palette name, not a numeric ID.
  • Brightness, Colour, and Speed become cap-touch sliders and display integer percentages.

Control Contract

The live WebSocket contract already supports the current edge controls and scene.smart. The main dashboard keeps only those live light-control surfaces; system-control back-end work is retained for a separate dashboard page.

  • Live now: primary.*, secondary.*, scene.smart.
  • Mode and Palette use a Tab5-local name registry matched to current K1 numeric values.
  • The main page does not expose system controls; that page can be added without changing the live light-control contract.

Implementation Plan

  1. Refactor Tab5 layout only: keep the header separate, keep the first dashboard row compact, and leave four equal light-function rows in the left panel.
  2. Add direct Mode buttons in the right panel and name resolution for Mode and Palette using the Tab5-local K1 registries.
  3. Preserve protocol compatibility for value writes: UI labels change, but the live command fields stay unchanged.
  4. Keep system-control work out of the main page; future system UI gets its own dashboard route and explicit ACK-backed controls.
  5. Validate with static tests, Tab5 build, upload, and USB serial proof. Do not use host WiFi to join the AP.

Acceptance Checks

  • No visible bottom tab/button row on the first control surface.
  • Header is not used for Primary, Secondary, or Scene controls.
  • First dashboard row has exactly three compact buttons: Primary, Secondary, Scene.
  • Primary, Secondary, and Scene buttons do not print secondary metrics under their titles.
  • Left-side controls stay readable at 1280x720 with no text overlap, including long palette names.
  • Mode and Palette never expose bare numeric IDs as the primary user value.
  • Right rail contains Mode buttons only, and excludes disabled legacy modes.
  • Every live command remains ACK-backed through the existing WebSocket client.
