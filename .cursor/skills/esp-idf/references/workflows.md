## PlatformIO + IDF Build Flow

This project builds with PlatformIO wrapping esp-idf 5.4.1. The `platformio.ini` controls the IDF version, sdkconfig overrides, and build flags.

```bash
# Build default environment (k1_hardware)
pio run

# Build specific environment
pio run -e k1_hardware_trace_dev

# Clean + rebuild (use when sdkconfig or partition table changes)
pio run --target clean && pio run

# Type-check only (project verification command)
bun run check-types
```

**Environments in this project:**

| Environment | Use |
|-------------|-----|
| `k1_hardware` | Production — default |
| `k1_bench_reference` | Alternate GPIO map for bench unit |
| `k1_hardware_trace_dev` | MabuTrace enabled — NEVER ship |
| `k1_hardware_harness` | Diagnostic capture mode |

See the **platformio** skill for full `platformio.ini` structure and `-D` flag patterns.

## sdkconfig Override Workflow

NEVER edit `sdkconfig` directly — it's generated by CMake and will be overwritten. All overrides go in `sdkconfig.defaults` (committed) or via `build_flags` in `platformio.ini`.

```ini
# platformio.ini — existing pattern for IDF config overrides
[env:k1_hardware]
build_flags =
    -DSB_TEMPO_V2=1
    -DSB_ONSET_V2=1
    -DCONFIG_ESP32S3_SPIRAM_SUPPORT=y
    -DCONFIG_SPIRAM_MODE_OCT=y
```

```
# sdkconfig.defaults — persistent IDF KConfig overrides
CONFIG_ESP32S3_SPIRAM_SUPPORT=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_FREERTOS_HZ=1000
CONFIG_ESP_SYSTEM_PANIC_PRINT_REBOOT=y
```

**Iterate-until-pass workflow for sdkconfig changes:**

1. Edit `sdkconfig.defaults` or `build_flags`
2. Run `pio run --target clean`
3. Run `pio run` — watch for `sdkconfig` conflict warnings in output
4. If conflicts appear, inspect `.pio/build/<env>/sdkconfig` for the generated result
5. Repeat until build succeeds with no KConfig warnings

### WARNING: PSRAM Config Mismatch

**The Problem:** Setting `CONFIG_SPIRAM_MODE_OCT` without `CONFIG_ESP32S3_SPIRAM_SUPPORT` causes silent PSRAM init failure at boot. `heap_caps_malloc(MALLOC_CAP_SPIRAM)` returns null everywhere.

**Why This Breaks:** The device boots successfully (no panic), but all PSRAM allocations fail. Diagnostic pool initialization silently degrades; the effect is only visible under heavy diagnostic load, not in normal use.

**The Fix:** Both keys must be set together. After any sdkconfig change, verify PSRAM at boot:
```cpp
log_i("PSRAM: %u bytes free", heap_caps_get_free_size(MALLOC_CAP_SPIRAM));
```

## Partition Table Changes

The partition table is defined in a CSV file referenced from `platformio.ini`. The 16 MB flash on the ESP32-S3-N16R8 is divided across app, OTA, NVS, and diagnostic storage.

```bash
# View current partition table (requires connected device)
pio run --target upload  # upload_guard.py verifies chip ID first
esptool.py --port <port> read_flash 0x8000 0x1000 ptable.bin
gen_esp32part.py ptable.bin
```

**Before changing the partition table:**
- [ ] Verify the device is the correct K1 unit (upload guard checks USB MAC + chip ID)
- [ ] Back up NVS if it holds calibration data: `esptool.py read_flash <nvs_offset> <nvs_size> nvs_backup.bin`
- [ ] Update the CSV, rebuild clean, and re-flash the full image (not OTA — partition changes require full flash)
- [ ] Verify with `gen_esp32part.py` that offsets don't overlap

## Flash and Upload Guard

This project uses `k1_upload_guard.py` to prevent flashing wrong firmware to wrong hardware. It checks USB MAC and chip ID before `esptool.py` runs.

```bash
# Correct upload path — guard runs automatically
pio run --target upload

# NEVER bypass the guard:
# esptool.py write_flash ...  ← skips MAC/chip verification
```

If the guard rejects the device:
1. Check that the connected device is the correct K1 unit
2. Verify the USB MAC in `k1_upload_guard.py` matches `pio device list` output
3. Do NOT add MAC exceptions without Captain approval — this gate prevents production firmware on dev boards

## Debugging with Serial + esp_log

```cpp
// GOOD — IDF structured logging (survives production stripping)
#include "esp_log.h"
static const char* TAG = "AudioPipeline";
ESP_LOGI(TAG, "tempo=%.1f bpm confidence=%.3f", bpm, conf);
ESP_LOGW(TAG, "beat overrun: %lld µs past deadline", overrun_us);

// For development-only trace (stripped in k1_hardware):
#ifdef SB_TRACE_ENABLED
  MABU_TRACE_BEGIN("goertzel_frame");
#endif
```

**Log levels:** `ESP_LOGE` (error) > `ESP_LOGW` (warn) > `ESP_LOGI` (info) > `ESP_LOGD` (debug, stripped in production).

Set the log level per component in `sdkconfig.defaults`:
```
CONFIG_LOG_DEFAULT_LEVEL_INFO=y
CONFIG_LOG_MAXIMUM_LEVEL_DEBUG=y
```

**Serial monitor:**
```bash
pio device monitor  # 115200 baud, CDC USB
```

For MabuTrace timeline capture (dev-only, `k1_hardware_trace_dev` env only), see the project's `diag/sb_trace.h` — do not use in production builds. The `k1_hardware_trace_dev` environment is explicitly marked non-shippable in `platformio.ini`.
